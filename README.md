# Process Discovery

Приложение помогает небольшим компаниям понять, чем занимаются сотрудники, и найти повторяющиеся задачи, которые можно упростить или автоматизировать. Сотрудник рассказывает о работе в чате с AI-интервьюером; руководитель видит подтверждённые задачи, а при необходимости может разобрать процесс подробнее.

## Как это работает

1. Руководитель регистрируется, создаёт организацию и копирует ссылку в разделе **«Команда»**.
2. Сотрудник открывает ссылку, указывает имя и email и попадает в интервью. При первом запуске показывается короткий гайд по чату.
3. Интервьюер помогает описать задачи, ручные действия, используемые программы, частоту и затраты времени. Интервью можно завершить досрочно или продолжить позже по той же ссылке с тем же email.
4. Сотрудник проверяет и подтверждает резюме. После завершения повторное интервью не начинается.
5. Руководитель открывает **«Задачи сотрудников»** и смотрит задачи каждого человека. В разделе **«Разбор процессов»** доступны найденные кандидаты, источники, карты и анализ; общие результаты отображаются в аналитике.

Результаты модели — отправная точка для обсуждения с сотрудниками, а не проверенное заключение о том, что именно следует автоматизировать. Не все задачи в интервью обязательно разобраны подробно.

## Быстрый запуск

Нужны Node.js **20.9 или новее**, pnpm и доступ к OpenAI-совместимому LLM API. Версия pnpm указана в `package.json`.

В PowerShell из папки проекта:

```powershell
pnpm install
Copy-Item .env.example .env
```

Откройте `.env`: задайте собственный `AUTH_SECRET`, адрес, ключ и имя модели в `LLM_*`. Затем создайте базу и запустите приложение:

```powershell
pnpm db:push
pnpm dev
```

Откройте [http://localhost:3000](http://localhost:3000) и зарегистрируйте организацию. В macOS или Linux вместо `Copy-Item .env.example .env` используйте `cp .env.example .env`.

Для просмотра интерфейса с готовыми данными можно выполнить `pnpm seed` после создания базы. Команда **удаляет и создаёт заново** демо-организацию с названием «Демо-ООО „Ромашка“» и её связанные данные. Вход владельца: `demo@demo.io` / `demo1234`. В демо уже есть сотрудники с завершёнными интервью и пример разобранного процесса.

## Настройки окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Адрес базы. По умолчанию `file:./dev.db` — файл `prisma/dev.db`. |
| `AUTH_SECRET` | Секрет Auth.js для сессий. Сгенерируйте собственное случайное значение, например `openssl rand -base64 32`. |
| `LLM_BASE_URL` | Базовый адрес OpenAI-совместимого API, например `https://api.openai.com/v1`. |
| `LLM_API_KEY` | Ключ провайдера. Значение обязательно для адаптера, в том числе при использовании локального совместимого API. |
| `LLM_MODEL` | Имя модели у выбранного провайдера. |

Интервью, извлечение данных из документов, сборка карты и часть анализа используют LLM; без настроенных `LLM_*` эти функции не работают. Изменения `.env` применяются после перезапуска сервера. Для проверки подключения войдите как владелец и откройте `/api/health/llm`: запрос выполнит небольшой вызов модели.

Ответы интервью и данные загруженных документов передаются настроенному LLM-провайдеру для обработки. Выбирайте провайдера с учётом того, какие сведения сотрудники могут сообщить.

## Приглашение и доступ

- Владелец входит с email и паролем. На странице команды он копирует общую ссылку и самостоятельно отправляет её сотрудникам.
- Сотрудник входит по ссылке, указав имя и email. Подтверждение email и пароль сотрудника сейчас не требуются: любой, кто знает ссылку организации и email сотрудника, может войти под его именем и увидеть или продолжить его интервью. Учитывайте это при выборе данных для интервью.
- Для продолжения незавершённого интервью сотрудник должен открыть ссылку той же организации и ввести тот же email. Ссылка не открывает аккаунт владельца или сотрудника другой организации.
- Код внутри ссылки используется приложением для определения организации; отдельно вводить его сотруднику не нужно.

## Разбор процессов

В разделе **«Задачи сотрудников» → «Разбор процессов»** руководитель может открыть существующий процесс или создать новый. Для него доступны:

- участники и источники: подтверждённые интервью и документы PDF, DOCX или XLSX размером до 10 МБ;
- построение и редактирование карты процесса, комментарии и вопросы для уточнения;
- анализ шагов, оценка затрат времени и возможности автоматизации, а также результаты для сравнения в разделе аналитики.

После подтверждения интервью приложение пытается связать найденные задачи с существующими процессами или предложить их как кандидатов. Эти связи и выводы следует проверять: модель может ошибаться или упустить контекст.

## Команды

| Команда | Действие |
| --- | --- |
| `pnpm dev` | Запустить сервер разработки. |
| `pnpm build` / `pnpm start` | Собрать и запустить приложение. |
| `pnpm db:push` | Применить схему Prisma к базе. |
| `pnpm db:studio` | Открыть Prisma Studio. |
| `pnpm seed` | Пересоздать демо-данные. |
| `pnpm test` / `pnpm test:watch` | Запустить тесты один раз / в режиме наблюдения. |
| `pnpm lint` | Проверить код линтером. |
| `pnpm exec tsc --noEmit` | Проверить типы TypeScript. |

В PowerShell, если выполнение `pnpm.ps1` запрещено политикой системы, используйте `pnpm.cmd` вместо `pnpm`.

## Устройство проекта

Приложение построено на Next.js App Router, React и TypeScript. Prisma работает с SQLite; авторизация реализована через Auth.js. Интервью использует OpenAI-совместимый API, а ответы сервера передаются в чат через SSE. Для карты используется `@xyflow/react`.

```text
prisma/schema.prisma          Модель данных SQLite
prisma/seed.ts                Демо-данные
src/app/                      Страницы и API
src/components/               Интерфейс, чат, гайд и карта
src/lib/agent/                Сценарий интервью и обработка результатов
src/lib/llm/                  Адаптер LLM API
src/lib/schemas/              Схемы и типы данных
src/lib/scoring/              Расчёт показателей анализа
src/lib/files/                Извлечение текста из документов
uploads/                      Загруженные файлы
```
